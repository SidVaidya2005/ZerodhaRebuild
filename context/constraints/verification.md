# Constraints — Verifying in a real browser

> **Reference half of `context/constraints.md`.** Read this **before driving the app in a
> browser or believing an automated check** — not at session start.
> Six features have lost time to the traps below; every one of them cost a verification pass
> that reported a false result rather than failing outright.


- **`quotes` cannot show that a price advanced, and the per-minute record expires.** Its PK is `symbol`, so the tick upserts in place and the table only ever holds current state — "distinct minutes written" is always 1 however long the job has run. The per-run evidence is in `net._http_response`, which **`pg_net` retains for only ~6 hours**; gather it the same day, or fall back to `cron.job_run_details`, which is kept far longer. (F16, closed 2026-09-04)
- **A backgrounded tab freezes animations, dispatches no focus events, and silently drops `.click()`.** `element.focus()` sets `document.activeElement` and fires nothing; `HTMLElement.click()` on a Radix trigger does nothing at all — **dispatch a full `pointerdown/mousedown/pointerup/mouseup/click` sequence instead, which does work.** CSS animations never reach `animationend`, so a Radix dialog closed while hidden stays mounted at `data-state="closed"` and its overlay swallows later clicks — which also makes any focus-return check unjudgeable, not failing. **Read `document.visibilityState` before believing an automated check that says an interaction does nothing** — six features have lost time to this. Hover coordinates are in screenshot space, not CSS pixels: at `innerWidth` 1640 against a 1456-wide capture they differ by ~12%. (F17, F19, F20, F27, Phase 4 checkpoint)
- **A backgrounded tab paints a canvas but screenshots it blank.** Lightweight Charts' candles were genuinely drawn — sampling the canvas found 1,331 painted pixels in exactly the three expected colours — while the captured image showed an empty chart, so a screenshot is not evidence about canvas content unless the tab is foregrounded or the capture is headless. **Read `document.visibilityState` before concluding a chart is broken.** Headless puppeteer runs `requestAnimationFrame` normally and is the reliable path; it still needs an explicit wait, because `networkidle0` fires long before the canvas paints. (F40)
- **"Visible" means unoccluded, and a synthetic click cannot stand in for a trusted one.** macOS reports a fully covered window as `visibilityState: 'hidden'` even while `document.hasFocus()` is true, so foregrounding means arranging windows side by side — never fullscreen behind the terminal, which puts the browser in its own Space. And any code reading `document.activeElement` *at* the click, as the order ticket's `rememberTrigger()` does, sees null under a dispatched `pointerdown/…/click` sequence, because Chromium focuses a button only on a **trusted** mousedown: drive those checks with real input. (F30)
- **Kill `next start` by PID from `lsof -nP -iTCP:3000 -sTCP:LISTEN` before trusting any post-rebuild check.** `pkill` does not reliably stop it, and the surviving process keeps port 3000 and serves the *previous* build — which has silently invalidated a verification pass twice. (F03, F04)
- **`resize_window` does not change `window.innerWidth`** in macOS fullscreen; it reports success and does nothing. Measure inside a 375×760 `<iframe>`, or drive headless Brave through the `puppeteer-core` that ships under `lighthouse`. (F03, 1.00.06)
- **pnpm appends extra script arguments rather than substituting `$1`**, so `audit:a11y` silently audited `/` and returned a plausible score. The script is wrapped in a shell function; confirm the target by reading `finalDisplayedUrl` out of the report, not by trusting the score. (F05)
- **Do not nest `nohup … &` inside a backgrounded command.** The harness reports the wrapper's exit and never notifies on the real work, so a long verification appears to finish instantly. Background the waiting loop directly. (Phase 4 checkpoint)
- **Sample the breakpoint *boundaries*, not the comfortable widths.** Checking 375, 768 and 1440 hid a 202px sideways scroll on every terminal page from 1024 to ~1226 — the band opens exactly where `lg:` brought a 404px nav into a bar that could not hold it, and closes before 1440. `pnpm audit:overflow` now measures 1024 and 1280 too. (F37)
- **`puppeteer-core` is reachable only *through* `lighthouse`.** It is a transitive dependency, so pnpm's isolation makes a direct `require.resolve('puppeteer-core')` fail; use `require.resolve('puppeteer-core', { paths: [require.resolve('lighthouse')] })` rather than the `.pnpm/puppeteer-core@<version>` path, which breaks silently on a lighthouse bump. Judge a page load on `status === 304 || 2xx`, not puppeteer's `response.ok()`, which is 2xx only — the static marketing pages answer 304 from the second viewport onward. (F37)
- **A dispatched pointer sequence opens a Radix *Sheet* but not the order ticket.** The sheet's contents were fully measurable in a backgrounded tab; the ticket's trigger never opened, twice. A positive result from a dispatched sequence is trustworthy; a negative one is unjudgeable and needs a foregrounded window and real input. **Headless puppeteer's `page.mouse.click` is trusted input and does open the ticket**, which is how `capture:screenshots` shoots it. (F37, F40)
- **`axe-core` is reachable through `lighthouse`, like `puppeteer-core`** — it is what Lighthouse runs internally, so `require.resolve('axe-core', { paths: [require.resolve('lighthouse')] })` gets the engine with no new dependency. Read `.source` off it and inject that string; the module also exposes `version`, worth printing so a run says which engine judged it. (F38)
- **A theme audit must assert the theme it actually got.** F35 has the terminal layout apply `profiles.theme` client-side on every full load, so a `localStorage` value a script writes is overridden back on any `(terminal)` route — a "light" run silently measures dark. Read `documentElement.classList` after load and **fail** on a mismatch; the account's own toggle is the only way to set it. (F38)
- **Puppeteer's `response.ok()` is 2xx only, and a static page answers 304 from the second load onward.** A guard judging on `ok()` reads a cached success as a failure; judge on `status === 304 || ok()`. (F37)
- **A transient `PGRST303 "JWT issued at future"` renders a terminal error boundary that passes every route guard.** Pathname, HTTP status and theme all look right on a rendered boundary, so an audit hitting it silently measures the error page. It clears on reload; a check that must be conclusive asserts the page's own landmark rather than only its URL. (F38)
