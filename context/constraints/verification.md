# Constraints — Verifying in a real browser

> Read this part of `context/constraints.md` before using a browser to verify the app or
> trusting an automated check. These traps have produced false results in six features.
> A check that ran successfully may still have measured the wrong thing.

- `quotes` stores current state, not tick history. Its primary key is `symbol`, so each tick overwrites the row and "distinct minutes written" stays at 1. Per-run evidence lives in `net._http_response`, retained by `pg_net` for only about six hours. Gather it the same day or use the longer-lived `cron.job_run_details`. (F16, closed 2026-09-04)
- Check `document.visibilityState` before judging an interaction. A background tab freezes animations, fires no focus events, and can ignore `.click()`. `element.focus()` may change `document.activeElement` without firing events; `HTMLElement.click()` does nothing on a Radix trigger. A full `pointerdown/mousedown/pointerup/mouseup/click` sequence works for supported triggers. Frozen animations also prevent `animationend`: a closed Radix dialog can stay mounted at `data-state="closed"`, with an overlay blocking later clicks. Focus-return checks in that state are inconclusive. Hover coordinates use screenshot space: a 1456px capture of an `innerWidth` 1640 page differs from CSS pixels by about 12%. (F17, F19, F20, F27, Phase 4 checkpoint)
- A background tab can draw a canvas that appears blank in screenshots. Lightweight Charts had 1,331 painted pixels in the three expected colours while its capture showed no chart. Check `document.visibilityState`; use a foreground tab or headless capture to judge canvas output. Headless puppeteer runs `requestAnimationFrame` normally, but still wait explicitly for painting because `networkidle0` fires too early. (F40)
- A visible browser must also be unoccluded. macOS reports `visibilityState: 'hidden'` for a fully covered window even when `document.hasFocus()` is true. Arrange windows side by side; fullscreen behind the terminal places the browser in its own Space. Use real input for focus-dependent checks: the order ticket's `rememberTrigger()` sees null under a dispatched `pointerdown/…/click` sequence because Chromium focuses buttons only on trusted mousedown input. (F30)
- Before testing a rebuilt app, find the listener with `lsof -nP -iTCP:3000 -sTCP:LISTEN` and kill `next start` by PID. `pkill` can leave it running on port 3000, serving the previous build. This has invalidated two verification passes. (F03, F04)
- In macOS fullscreen, `resize_window` can report success without changing `window.innerWidth`. Measure within a 375×760 `<iframe>` or use headless Brave through the `puppeteer-core` dependency under `lighthouse`. (F03, 1.00.06)
- pnpm appends script arguments; it does not substitute `$1`. `audit:a11y` once silently audited `/` instead of the requested page. Its shell-function wrapper handles this now, but still check the report's `finalDisplayedUrl` before trusting a score. (F05)
- Do not put `nohup … &` inside a command that is already backgrounded. The harness reports the wrapper's exit without reporting completion of the real work. Background the waiting loop directly. (Phase 4 checkpoint)
- Test breakpoint boundaries as well as convenient widths. Checks at 375, 768 and 1440 missed up to 202px of horizontal overflow between 1024 and roughly 1226px, where `lg:` introduced a 404px nav into a crowded bar. `pnpm audit:overflow` also measures 1024 and 1280. (F37)
- Resolve `puppeteer-core` through `lighthouse`: `require.resolve('puppeteer-core', { paths: [require.resolve('lighthouse')] })`. pnpm isolates this transitive dependency, so a direct `require.resolve('puppeteer-core')` fails. A hardcoded `.pnpm/puppeteer-core@<version>` path breaks when Lighthouse changes. Accept `status === 304 || 2xx` on page loads: static marketing pages return 304 from the second viewport onward, while puppeteer's `response.ok()` accepts only 2xx. (F37)
- A dispatched pointer sequence can open a Radix Sheet but fail to open the order ticket. The sheet was measurable in a background tab; the ticket failed twice. A successful synthetic interaction is useful evidence, but a failed one needs a foreground window and real input before it can be judged. Headless puppeteer's `page.mouse.click` is trusted input and opens the ticket for `capture:screenshots`. (F37, F40)
- Resolve `axe-core` through Lighthouse too: `require.resolve('axe-core', { paths: [require.resolve('lighthouse')] })`. Lighthouse already includes it, so no dependency is needed. Inject the module's `.source` string and print its `version` to record which engine ran. (F38)
- Assert the actual theme after loading the page. On each full `(terminal)` load, F35 reapplies `profiles.theme` client-side and can overwrite a scripted `localStorage` preference. Read `documentElement.classList` and fail on a mismatch. Use the account's own toggle to set its theme. (F38)
- Check the page's own landmark as well as its URL, status and theme. A transient `PGRST303 "JWT issued at future"` can render a terminal error boundary with all three looking correct, so an audit measures the error page unnoticed. Reloading clears it. (F38)
