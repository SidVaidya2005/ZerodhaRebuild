# Constraints — Live prices, interpolation, and quote providers

> Read this part of `context/constraints.md` before changing a price display, the quote
> store, provenance, or a provider. `architecture.md` contains the always-read provenance
> invariants. This file explains the implementation details and mistakes behind them.

## Live prices and interpolation

- Interpolation moves along the closed segment between the previous and current server anchors. It must not invent jitter beyond either endpoint. This is stricter than staying "within X%" of an anchor and can be tested at tier 1 without a DOM. The build plan's earlier bounded "micro-ticks" wording was corrected. (F19)
- Dashboard money tiles update when an anchor arrives and never tween between anchors. The architecture invariant for monetary totals overruled a conflicting description of these tiles. They still update alongside the ticking watchlist; the index strip may remain ambient. (F21)
- Never subscribe a component to the entire `state.quotes` map. Interpolation rebuilds it each frame, causing about 60 renders per second for roughly 800ms after a tick, including an expensive Recharts SVG. Select flat maps of primitive values with `useShallow`. (Phase 3 checkpoint)
- Rows read `store ?? prop` and seed the store in an effect. The server render and first client render then match, and a missing quote still displays an em dash. (F19)
- `seedQuotes` must accept a server row when its `fetchedAt` is newer. Checking only whether the symbol exists is insufficient: the layout's store survives navigation and can retain the first seed all session when Realtime delivers nothing. (F19)
- Before subscribing, await `getSession()` and `realtime.setAuth(token)` before `.subscribe()`, and always supply a status callback. Realtime checks each subscriber's JWT against RLS, while the cookie session loads asynchronously. Subscribing too early can report `SUBSCRIBED` but silently deliver no rows. (F19)
- The quote channel listens only for `UPDATE`. A symbol's first quote is an `INSERT`, so adding a symbol to an open page requires an `INSERT` subscription or `router.refresh()` to make that first row visible. (Phase 3 checkpoint)
- Supply provenance for server rows too, using `serverProvenance(row, now)`. `PriceWithProvenance` displays an em dash for null provenance, so `live ? … : null` hides every SSR price. Hydration masks this bug; inspect the fetched HTML to find it. (F20)
- Use `anchorProvenance()` when rendering an anchor. `provenanceOf` derives `isInterpolated` from the store's current tween through `ltp !== anchor`, so it can label a server-anchor price "interpolated" even though the caller did not render the moving value. Monetary displays always use anchors. (F30)
- Make provenance available beyond hover. Tie `sr-only` facts to each price with `aria-describedby` as well as showing a HoverCard. Touch users cannot hover, and screen readers never trigger it. (F20)
- Mute STALE prices only. Every price in this build is SIMULATED; muting simulated prices would grey out the whole terminal and communicate nothing. (F20)
- Feed the source badge only symbols that currently display a price. `worstSource([])` deliberately returns STALE, so including missing quote rows would keep the badge STALE. An em dash makes no price claim. (F20)
- Share one ticking clock from the terminal layout for the badge and individual prices. Otherwise the same render can show a DELAYED row under a STALE badge. F17's market-status pill keeps its own timer because it must update on the session boundary. (F20)
- Recompute the watchlist's day change client-side once prices are live. It is display-only and never stored, so it respects the rule against calculating persisted money in TypeScript. (F19)
- The index strip is an equal-weighted mean day change across the project's priced universe, with advances, declines and the constituent count visible. It must not claim to be NIFTY 50, SENSEX or BANK NIFTY: none exists in the data. A simulated level under one of those names would invent a prominent piece of market data. (F17, F21)
- Opening the mobile sheet makes `touch_symbol_demand` fire twice because the rail and sheet both mount `WatchlistPanel`. The RPC is idempotent, so this is harmless. Hoisting the hook was identified as a possible F37 improvement. (F18)
- Realtime changes to `orders` trigger `router.refresh()` so the page also receives the cash and margin moved by that fill. Keep the server-side `user_id` channel filter. RLS controls delivery, but an unfiltered subscription still requires each row to be checked for every subscriber. (F27)
- Lightweight Charts treats timestamps as UTC and has no timezone support. It once labelled an NSE session 03:45–10:00. Shift both timestamp forms to IST at the render boundary, as the library prescribes. Shifted values exist only for wall-clock labels; `candles.ts` retains true UTC instants. (F33)
- Generate candles only for missing slots and the slot still forming. A pure generator alone does not preserve history because each batch bridges to an anchor that moves during the day. Regenerating stored slots would rewrite past candles. (F33)
- Daily candle freshness depends on whether a newer bar can exist. `isFresh` compares the stored IST date with `lastTradingDate(at)`. A 24-hour TTL kept yesterday's series fresh until 15:35 today, blocking today's bar, then repeatedly fetched an unchanged Friday over the weekend. (Phase 5 checkpoint)
- Close the final bar of every interval on `ltp`. Once the session opens, `candleSlots` includes today. Anchoring it to `prev_close` made today's forming daily candle show yesterday's close and contradict the header, violating F33's anchor rule. (Phase 5 checkpoint)
- Trim intraday series by IST date before serving them. `readStored` has no date bound and `prune_candles` removes only the previous day, so "1D" once showed two sessions on day D+1. `windowSeries` selects the last N distinct dates actually present; this also lets a Sunday 1D request show Friday without a holiday set. (Phase 5 checkpoint)
- Cached candle series report their stored `fetched_at`. Claim the current instant only after a refresh has written rows; using `now` on a cache hit overstates freshness. (Phase 5 checkpoint)
- Check elapsed span before showing a "52-week" range. Bar count cannot prove a year of coverage: the stock page once passed a 1M window of 22 daily bars, all within 365 days, and labelled its extrema as 52-week values. `fiftyTwoWeekRange` checks `FIFTY_TWO_WEEK_MIN_SPAN_DAYS`. (Phase 5 checkpoint)
- Render the chart once per server render; let only the header tick. The `FIVE_MIN` TTL makes the series at best five minutes fresh, so growing its rightmost bar live would imply unsupported precision. Subscribing its canvas to the quote store would also cause roughly 60 renders per second during interpolation. (F33, F19)
- Candle retention runs through `prune_candles()` on a separate `pg_cron` schedule. Do not put it in `market-tick`: F16 is parked until the project's end, and verification there would need deployment and waiting. SQL retention can be tested at tier 2. (F33)

## Quote providers

- The simulator is the entire provider chain by permanent scope decision. Twelve Data's free plan has no NSE symbols, Yahoo blocked this machine's IP, and no keyless source proved workable. Every price therefore badges `SIMULATED`, matching public copy and `project-overview.md`. Adding a real provider requires reversing those scope and copy edits, including `DataHonesty`'s `DELAYED` chip, and measuring `QUOTE_DELAYED_WINDOW_MS`, which remains unexercised and based on an assumption. (F14, F15, 6.00.04, decided 6.00.05)
- A live API check with a real key confirmed that Twelve Data's missing NSE access is a plan restriction, not a symbol-format error. Even with access, 800 credits per day would not support one-minute ticks. F14's remaining chain was Yahoo → simulator; the current simulator-only decision above supersedes that provider plan. (F14)
- If Yahoo is tried again, throttle probes to roughly 1.5s apart and cache progress so a limited run can resume. Its burst limit acts by IP and outlasts in-process backoff. A 429 says nothing about a symbol's existence; only 404 means unknown. This is retained as the only measured evidence about that endpoint. (F14)
- The current circuit breaker cannot retain failures across ticks. `createQuoteService` stores counts in its closure and is constructed per request, giving each minute a new `failureThreshold`. Moving state to a table was an obligation for a Yahoo feature. It is now permanently unnecessary for the always-answering simulator, but returns if a real provider is restored. (F15, closed 6.00.05)
- The provider seam exists; the token-bucket limiter remains unbuilt by permanent decision. A local simulator makes no outbound requests, so there is nothing for a bucket to limit. (F15, closed 6.00.05)
- The simulator starts from a real NSE close seeded from bhavcopy into `instruments.prev_close`. That close is seed data, never a quote: do not add an `NSE_BHAVCOPY` provider value, derive provenance from it, or display it as live. (F15, narrowed F16)
- At the first in-session tick, `quotes.prev_close` rolls from the quote row rather than a separate schedule. The roll repairs a missed run and is idempotent within a session. `loadAnchors` must prefer this value to `instruments.prev_close`; using the original seed trapped prices within 5% of the universe's seeding day. (F16)
- Include watchlists in the tick's demand union. `symbol_demand` had no write path before F18, so omitting watchlists would originally have refreshed zero symbols and left the write path untested. (F16)
- Keep refresh separate from seed. `fetch-reference-data.mts` calls NSE and Yahoo and rewrites committed JSON; `seed-reference.mts` only reads and upserts that JSON. Depending on undocumented NSE endpoints during every seed would be unreliable and leave no data diff to review. (F14)
- Reference refresh must probe every `yahoo_symbol` and refuse to write if any probe fails. Sampling five symbols checks only 2.5% of the universe and can miss a never-quoting symbol until Phase 5. The committed seed records `yahoo_validated: false` because the `${symbol}.NS` mapping has not been confirmed live. (F14)
