# Constraints — What the test tiers have already taught us

> Read this part of `context/constraints.md` before writing or debugging a test in any tier.
> `code-standards/testing.md` explains the four tiers. This file records their known limits
> and the traps found while running them.

- Tier 4's margin parity test copies `reserve_margin`'s branch selection into TypeScript and sends only the arithmetic to Postgres. If the engine changes which branch nets against a position, parity can stay green while the ticket becomes wrong. `08-margin.sql` tests the function directly, but the comparison of branch selection across languages is still missing. **Not fixed.** (Phase 4 checkpoint)
- The full suite cannot pass with an open MIS position in the account during an open market. Tier 3's square-off pre-flight deliberately refuses to sweep real positions. Run `pnpm test:all` with a flat account or a closed market. (Phase 4 checkpoint)
- Check existing tier-2 coverage before adding assertions. `10-orders.sql` already covered F31's exit and F32's reset, so those features cite it. Copying a passing assertion adds no coverage and creates two versions that can drift. (F31, F32)
- Tier 3 commits into the production database. The first connection must commit to prove that a second cannot fill the same order. Always require `ALLOW_RACE_TESTS`, give fixture rows a recognisable prefix, and clean up in `afterEach` on success and failure. A process crash can still leave rows behind; that residual risk is accepted. (1.00.03)
- Through the pooler, identify a blocked backend by pid rather than `pg_stat_activity.query`. A `query ilike` poll timed out one run in three because the blocked backend's `query` still showed `begin`. Capture its pid inside the transaction, which session mode pins, then poll `pg_blocking_pids($1)`. (F29)
- A race test that pre-locks a row also commits to a lock order. `squareoff.race.test.ts` staged its race on a position row; after the sweep's lock order was fixed, the test itself caused an inversion and deadlocked. Stage the interleaving on the first lock taken by the function under test. (F29)
- Run tier-3 pre-flight before seeding and check every symbol. Excluding the fixture symbol hides leftovers from a crashed run. A stray row makes the sweep cover several rows, changing the interleaving the test was meant to exercise. (F29)
- `supabase test db` needs Docker even with `--db-url`. It connects remotely, then tries to run `pg_prove` in a container and fails with `LegacyDockerRunError`. Use `scripts/run-pgtap.mts`, which reads pgTAP's TAP output as text rows. (F09)
- The tier-2 runner must reject a plan mismatch as well as `not ok` and SQL errors. A suite that declares `plan(2)` but runs one assertion is broken. All three failure modes were observed failing before the runner was trusted. (F09)
- Enable pgTAP in a tracked migration. The runner must not create it ad hoc: otherwise a fresh database can appear healthy while missing an extension the tests need. (F09)
- Keep tier 2 outside Vitest. Its standalone TypeScript runner is `node scripts/run-pgtap.mts`, so `pnpm test` cannot accidentally pick up a database suite. (F09)
- `scripts/run-race.mts` checks permission before starting Vitest. With no permission, a tier-3 run must not even import `pg`. (F09)
- Test a negative claim with a positive control. Vitest suppressed `console.log` in both cases during an early check; seeing no output was not proof that one path had been blocked. (F09)
- The owning database role bypasses RLS. Scope its pgTAP assertions to fixture rows so they do not include real data. Assertions after `set local role authenticated` are scoped by RLS. (F13)
- Tests of deliberately global functions must clear the relevant global state. `select_demanded_symbols` reads demand across the system, so `04-market-tick` empties the demand tables. This is safe only because the suite always rolls back. (F16)
- `market-tick` reads its `session_at` override after checking the secret, so the override requires the same Vault credential. It changes only the session gate and square-off boundary. Rows still use `now`, the response says `sessionOverride: true`, and `place_order` is unaffected. (Phase 4 checkpoint)
- Market-time functions accept the calendar as an argument so tier 1 can challenge their results. `marketStatusAt(at, holidays)` and `isTradingSessionAt(at, holidays)` are pure; database-backed wrappers load the calendar and call them. (F15)
- The app and Edge Function share the market-hours core, so the planned drift test was unnecessary and was never written. Deno imports `supabase/functions/_shared/` relatively; the app imports it through `@shared/*`. The Edge Function cannot import from `src/`. Keeping one copy removes the duplication that test would have policed. (F16)
- Tier 1 uses Vitest's node environment and tests pure logic. It has no jsdom or Testing Library; neither is an approved dependency. Verify component behaviour in a browser. (F01)
- Vitest cannot import `server-only`, so `vitest.config.mts` aliases it to the package's `empty.js`. `next build` still resolves the throwing entry for client bundles, and the falsifiability check tests that build protection. (F01)
- `fetch-reference-data.mts` treats every failed probe as a nonexistent symbol. A transient Yahoo 5xx can therefore abort a roughly five-minute, 200-symbol run; only 404 should decide that a symbol is unknown. **Not fixed:** the script is manual, infrequent and can be rerun. (F14)
- A tier-2 suite that clears a reference table must clear its dependants too. After F26 allowed real `orders`, a real order made `pnpm test:db` fail on `orders_symbol_fkey`. Clear the dependent rows inside the test transaction; the deletes roll back. (F26)
