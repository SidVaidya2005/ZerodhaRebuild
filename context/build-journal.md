## How this file is maintained

This file grows for the life of the project and is **not** part of the session read order.
Nothing here is required to make a decision — anything that still constrains future work gets promoted to `constraints.md`, which is the file consulted during ordinary work.
That separation is what keeps the cost of knowing "what binds" from growing with the length of the build.

- **Append a dated entry after every completed feature**, under the current phase: decisions made, gotchas hit, verification results.
- **Compact at every phase checkpoint, never continuously.** When a phase closes:

  2. **Collapse** the phase's per-feature entries into a handful of summary bullets.
  3. **Drop every `Verified:` line** — it has done its job once the next feature passes.
- Only the current phase keeps full per-feature detail. Earlier phases stay compacted, newest first.

Compaction is recoverable: this file is committed, so `git` history holds every detail ever removed.

## Phase 2 — Data Foundation & Auth

### Feature 18 — Watchlist sidebar  *(2026-08-22)*
- Decision: **search filters a preloaded universe in the browser, and the trigram index the plan called for was never built.** 200 rows of symbol/name/exchange is one packet, and Postgres seq-scans a table that small whatever index sits on it — the index would have been created, tested and never chosen by the planner. Removing the query also removed the debounce, the loading state and the 300ms budget the plan was written around.
- Decision: **reorder is move-up / move-down, not drag.** No drag-and-drop dependency exists, native HTML5 drag has no keyboard path, and `@dnd-kit` would be ~40KB used by one surface. Buttons write the same `sort_order`, are reachable by tab, and leave drag available later over the same Server Action.
- Decision: **the change is computed in a `security_invoker` view**, not in the panel. `CLAUDE.md` puts money arithmetic in Postgres; the view also makes the panel one round trip and gives F30 and F33 the same shape to read. A null or absent quote yields a null change rather than a fabricated zero.
- **Finding — the view filtered twice and only one of the filters was load-bearing.** It carried `where w.user_id = (select auth.uid())` *and* `security_invoker`. Falsifying the isolation showed the predicate alone was holding the line: with invoker rights turned off, another user still saw nothing, because the WHERE had already filtered them out. So the invoker setting was **completely untested**, and a later edit could have dropped it with the whole suite still green. The predicate is application code doing RLS's job, against `CLAUDE.md`'s security-boundary rule, so a second migration removed it. Re-falsified: invoker off now leaks 13 rows — every user's list — and invoker on leaks none. **The passing test was the thing that nearly hid this**, which is the phase-1 lesson again.
- **Finding — the rows rendered correctly and were invisible.** shadcn's `Command` base class is `flex h-full w-full flex-col`; inside the panel's flex column that `h-full` claimed the entire height and squashed the list below it to `height: 0`, parked one pixel below the viewport. The DOM held ten correct `<li>` the whole time — `innerText` read them back in full — so every check short of measuring a bounding box called this working. `h-auto shrink-0` fixes it, and unlike F17's sheet width this one *is* a plain utility, so tailwind-merge overrides it normally.
- **Finding — `opacity-0` hides a control but does not remove it from layout.** The four hover actions sat as flex siblings, so they permanently consumed ~112px of a 256px row: the symbol truncated to "BH…" and the change wrapped onto two lines while nothing was hovered. Absolutely positioning the action strip gives the width back and leaves the reveal behaviour unchanged.
- Gotcha: **cmdk's default filter is a fuzzy subsequence match, which is wrong for a symbol list.** It answered "rel" with most of the 200-row universe — `GROWW` scored because *Billionbrains Garage Ventures* contains r, e and l in order. `shouldFilter={false}` plus a pure `searchUniverse` ranker (exact symbol, symbol prefix, name prefix, then substrings, capped at 20) answers "rel" with exactly RELIANCE. The cap was in the original build plan and I had dropped it when moving filtering client-side; the tier-1 suite now pins both the ranking and the cap.
- Verified end to end in the browser, signed in: remove RELIANCE → gone; navigate to `/orders` → still gone, which is what proves `revalidateTerminal` reaches the sibling routes rather than only the current one; search "rel" → one result; add → appended at the bottom with the query cleared; move up → swaps with KOTAKBANK; navigate to `/holdings` → the new order held. Move-up on the first row and move-down on the last are both disabled.
- Verified: all ten on-screen symbols land in `symbol_demand` within seconds of render, with `priority` still 0 — the column the client must never be able to raise.
- Verified: `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm format:check` all 0; `pnpm test` 175 across 14 files; `pnpm test:db` 10 files with `05-watchlist.sql` at 30/30, covering both denial modes separately — `42501` for a role holding no grant, a returned `0` for the definer function's own session guard.
- Note for F19/F20: nine of the ten watched symbols have **no `quotes` row at all**, so they render an em dash rather than a price. That is the tick's data state, not this feature's — the one symbol that does have a quote renders `+4.92 (+0.25%)` correctly — but it means the sidebar looks mostly empty until the tick has run through a live session.

### Feature 17 — Terminal shell layout  *(2026-08-22)*
- Decision: **the rail and the sheet are exported separately, because they live in different parts of the page.** One `WatchlistSidebar` rendering both put the 288px `aside` inside the header's `flex h-16` row, where it was clipped to the nav's height, had its own heading cut off, and pushed the brand, index strip and pill sideways until they wrapped. `WatchlistRail` is now a column beside `<main>` in the layout and `WatchlistSheet` is the trigger in the nav; both still render the same `WatchlistPanel`, so F18 fills one component and both breakpoints follow.
- Decision: **the pill takes the server's instant as `serverNow` rather than initialising from `null` or from `new Date()`.** A `null` initial state renders a placeholder on every load; reading the clock during render hydrates different text than the server sent. Passing the instant makes the first client render identical to the server's, and the timer takes over from the browser's clock afterwards. This also cleared an ESLint `react-hooks/set-state-in-effect` error rather than suppressing it.
- **Finding — a bare `w-full` cannot override a variant-prefixed base class, and it fails silently.** `SheetContent`'s base is `data-[side=left]:w-3/4`; tailwind-merge groups by variant, so `className="w-full"` landed in a different group and both survived, leaving the sheet at exactly three-quarters of the viewport. Nothing errors, nothing warns — the sheet just is not full-screen, which `DESIGN.md` → Collapsing Strategy requires under 768px. The override has to repeat the variant: `data-[side=left]:w-full data-[side=left]:sm:max-w-none`. **Measured, not eyeballed**: 375px in a 500px viewport, exactly `w-3/4`, is what named the cause.
- **Finding — the nav bar overflowed at 375px** by 4px at `gap-4 px-4`, then still by 32px at 320px. Fixed to `gap-3 px-3` below `sm` with the wordmark one step smaller, which lands 360, 375 and 414 exactly on the viewport width. **320px still overflows by 32px and is left open** — below the width the plan set, and closing it means dropping something from the bar.
- Gotcha: **a backgrounded tab freezes CSS animations, and Radix will not unmount behind one.** Closing the sheet left the panel *and* its overlay in the DOM at full opacity with `pointer-events: auto`, swallowing every subsequent click on the page — which is what made the burger stop responding mid-session. The cause was not the component: `visibilityState` was `hidden`, `hasFocus` false, and the exit animation's `currentTime` was pinned at 0, so `animationend` never fired and Presence never tore the node down. Dispatching `animationend` by hand unmounted both nodes and made the burger clickable again, which is what proves the close path itself is correct. **Nearly filed as a product defect**; the check that separated them was reading `currentTime` twice rather than trusting `playState`.
- Gotcha: the OAuth callback is built from `NEXT_PUBLIC_SITE_URL`, not the request, so signing in against a dev server on any port other than 3000 sends Google's redirect to a port nothing is listening on. Sign-in appears to fail while it has actually succeeded up to the last hop. Verify on 3000, or the browser check cannot be done at all.
- Verified in the browser, signed in, by measuring the DOM rather than reading the screenshot: at `innerWidth` 1440 the rail is 288px and `<main>` 1152px with no horizontal overflow, the burger is `display:none`, and the index strip and all six nav links are present. Below the breakpoint the rail is `none`, the burger `flex`, the desktop nav `none`, and the pill drops to "Closed". The sheet opens full-bleed (500×589 in a 500×589 viewport) and closes cleanly, leaving nothing mounted.
- Verified: the pill reads Closed with "opens 09:00" outside a session, agreeing with the tick's own gate because it calls the same `marketStatusAt`. Both themes render the shell correctly — checked by reading computed backgrounds in each, not by eye.
- Verified: `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm format:check` all 0; `pnpm test` 168 across 13 files; `pnpm test:db` 9 files, 174 assertions. `pnpm build` lists all eight terminal routes as dynamic and leaves the public routes static.
- Not done here: terminal a11y. Lighthouse cannot reach these routes without a session, so it stays F38's. Two things noted for it — the burger's hit area is 32px against `DESIGN.md`'s 44px guidance, and `FundsSummary` is `hidden md:flex`, so available cash disappears below 768px.

### Feature 16 — Market tick Edge Function and schedule  *(2026-08-21, one item pending)*
- Decision: **the shared logic moved rather than being duplicated.** The plan called for copying `market-hours` into `supabase/functions/_shared/` and guarding the two copies with a tier-1 drift test. An Edge Function cannot import from `src/`, but nothing stops the dependency running the other way: `_shared/` now holds the one implementation, Deno reads it relatively and the app through a new `@shared/*` alias, mirrored in `vitest.config.mts` because `vite-tsconfig-paths` is not an approved dependency. A drift test earns its place when duplication is forced, as with F05's stack table; here removing the duplication removes the failure it would have policed.
- Decision: **the calendar readers moved too, after the tick was found carrying its own copy.** `loadHolidays` existed twice — once in `src/lib/market/market-hours.ts` with a tier-1 test, once inside `index.ts` with none — which is exactly what the decision above claims to prevent. They take a structurally-typed `HolidayReader` so `_shared/` still imports nothing and Deno can load it. Nothing in the app calls them until F20, so a compile-time assertion in the tier-1 suite proves a real `SupabaseClient<Database>` still satisfies that shape.
- Decision: **watchlists join the demand union**, which the build plan did not specify. `symbol_demand` has no write path until F18 and nobody holds anything, so without them `select_demanded_symbols` returns nothing and the tick's entire write path ships untested. A SQL function rather than a TypeScript query, so pgTAP tests the union and its ordering directly; `security definer` with execute revoked from every role, since it reads every user's holdings, positions and watchlists.
- **Finding — `verify_jwt` is not access control, and the plan had the fallback backwards.** `library-docs.md` carried a TODO to discover which credential satisfies the gateway; measuring it against the deployed function five ways answered something worse. No `Authorization` header is rejected by the platform with its own `UNAUTHORIZED_NO_AUTH_HEADER` before our code runs — but **`sb_publishable_…`, the key that ships in the browser bundle, returns 200**. So `verify_jwt` proves only that the caller read the JavaScript. The handler now compares an `x-scheduler-secret` against a Vault-held value in constant time before touching the database, and **refuses rather than falls open** when that secret is unset. The docs described this as contingency for a gateway that accepted no credential; it is necessary for the opposite reason, and it is the belt, not the braces.
- **Finding — the one real account had an empty watchlist, and the demand union was therefore empty.** `handle_new_user()` seeds the default by intersecting a fixed list against `instruments`, deliberately, because F13 ships before F14 and a plain insert would violate the foreign key. The account was created at 14:11 UTC, about an hour before F14 seeded the universe, so it got zero rows — a build-order artifact rather than a defect in the trigger. Backfilled by a one-shot idempotent migration scoped to accounts holding *nothing*, so a curated watchlist is never repopulated behind its owner's back. F18's sidebar and F20's pill would have hit the same emptiness later with less to point at.
- Gotcha: **that backfill turned `04-market-tick.sql` red, and the test was the thing at fault.** It cleared `watchlist_items` for its two fixture users and then asserted the *global* result of `select_demanded_symbols` — a function with no user filter, by design, because the tick asks what the whole system wants refreshed. It had been green only while the real account happened to hold nothing. F13's constraint says to scope owner-role assertions to their fixture; that cannot be applied when the function under test is deliberately unscoped, so the fixture clears every source table instead. Safe because the suite always rolls back, which was verified by re-reading the real rows afterwards rather than assumed.
- Gotcha: excluding the Deno entrypoint from `tsc` is easy to overdo. `supabase/functions/market-tick` is excluded — `jsr:` specifiers and the `Deno` global — while `_shared/` deliberately stays in the program. Confirmed by planting a type error in `_shared/market-hours.ts` and watching `pnpm typecheck` fail, then removing it; an exclusion that quietly swallowed the shared modules would have looked identical from the outside.
- Verified, by direct measurement against the deployed function: no `Authorization` header → 401 from the platform, never reaching the handler; publishable key alone → 401 in *our* response shape, which is what proves the gateway let it through; service role alone → 401; service role plus the scheduler secret → 200 `{"ok":true,"skipped":"MARKET_CLOSED"}`.
- Verified: three `pg_cron` runs one minute apart, each 200 with `skipped: MARKET_CLOSED` in `net._http_response` — scheduler, gateway, secret check and session gate proven end to end outside a session. The gate outranks the schedule at 08:45 IST (03:15 UTC, inside `* 3-10 * * 1-5`) and on Republic Day at 11:00 IST, both tier-1; `03-reference-data.sql` separately pins that date as really present in `market_holidays`.
- Verified: the demand union returns the 10 backfilled symbols live; 200 demanded symbols yield exactly the cap of 50, the cap is the argument rather than a constant, and a delisted symbol is never selected however much it is watched. A forced provider failure still writes simulator rows — F15's chain tests already cover it, since the simulator is the last resort and cannot itself fail.
- Verified: `pnpm lint`, `pnpm typecheck`, `pnpm build` all 0; `pnpm test` 152; `pnpm test:db` 9 files with `04-market-tick.sql` at 13/13.
- **PENDING — replace this line on Monday 2026-08-24.** Two items need a live trading session and the cron window is weekdays only: that `quotes.fetched_at` advances for the demanded symbols with every row `SIMULATOR` and a null `provider_ts`, and that a capped run finishes inside ten seconds. The queries are in `progress-tracker.md` → Next.

### Feature 15 — Quote provider chain  *(2026-08-21)*
- Decision: **the simulator walks from a real NSE close.** `library-docs.md` said it seeds "from `instruments` reference data", but that table carried no price — a cold start had nothing to walk from and every symbol would have begun at an invented constant. `instruments.prev_close` is now seeded from the published bhavcopy, found on the **archive** host that F14 already reaches rather than the API that answers 403. MRF opens near ₹1,32,665 and YESBANK near ₹22.80; a shared constant would have priced them identically and made Phase 5's portfolio arithmetic meaningless.
- Decision: **the close is a seed, never a quote.** No `NSE_BHAVCOPY` value joins `quote_provider`, nothing writes it into `quotes`, and no surface renders it as a price. Every price still comes from a row carrying `provider = 'SIMULATOR'` and a null `provider_ts`, which `deriveSource()` renders as SIMULATED. Nullable on purpose: a fresh listing with no close makes the simulator report itself **unavailable** rather than creative.
- Decision: **the seam is built, the limiter is not.** `QuoteProvider`, an ordered chain and a per-provider circuit breaker, exercised against a deliberately failing fake. A token bucket in front of a local simulator caps nothing, so it waits for a provider that makes outbound requests. F14 is why the breaker earns its place now: the failure that mattered was not one bad response but continuing to hammer an upstream that had already said no, which is what kept Yahoo's block alive for forty minutes.
- Decision: **`market-hours.ts` is a pure core with database-backed wrappers.** `marketStatusAt(date, holidays)` takes its calendar as an argument so tier 1 can falsify it; `isTradingSession(supabase, at)` and `getMarketStatus(supabase, at)` load and delegate. `loadHolidays` **throws** rather than returning an empty set on a read error — an empty calendar is indistinguishable from a year with no holidays, and the failure it causes (trading on Republic Day, a square-off that never runs) is otherwise silent.
- Decision: **Asia/Kolkata is treated as a fixed UTC+05:30.** India has observed no daylight saving since 1945, so this is exact rather than an approximation — and the assumption is *checked*, not asserted: a test compares the arithmetic against `Intl` at five instants across the year, including both hemispheres' DST changes.
- Decision: pre-open is a **state but not a session**. `getMarketStatus` reports `PRE_OPEN` between 09:00 and 09:15 for F20's pill, while `isTradingSession` stays false — no quote is written and no order fills during the call auction. 09:00 is NSE's actual window and is not stated in the project docs, so it is a named assumption in `constants.ts`.
- Note: the quote windows are **unmeasured**. `architecture.md`'s standing TODO to measure Yahoo's real `regularMarketTime` lag cannot be done while Yahoo is deferred, so all three constants carry a comment saying so and what would change them.
- Gotcha, found by mutation testing: replacing the simulator's `prev_close` fallback with a constant did **not** fail the MRF/YESBANK spread test, because the ±5% clamp is anchored to `prev_close` and snapped the bad seed back into range. The behaviour is what `library-docs.md` specifies — clamp per session — but it means the clamp can mask a wrong seed, and only the "refuses to invent a price" assertion caught the change.
- Verified by falsification, four ways: a breaker that never opens fails two tests; a next-transition that is simply "tomorrow" fails the weekend and holiday skips; reading server-local hours instead of IST fails four tests under `TZ=America/New_York`; and dropping the `prev_close` fallback fails the no-anchor assertion.
- Verified: the suite passes identically under `TZ=UTC`, `TZ=America/New_York`, `TZ=Asia/Kolkata` and `TZ=Pacific/Kiritimati` (UTC+14). A market-hours test that only passes in one zone proves nothing about a server in Oregon.
- Verified: `LIVE` is structurally unreachable — the assertion sweeps all three providers across five ages and finds none. `pnpm test` 151, `pnpm test:db` 8 files / 152 assertions with four new `prev_close` checks, and `grep` confirms nothing under `src/lib/market/providers/` imports Supabase or calls `fetch(`.
- Verified: `pnpm lint`, `pnpm typecheck`, `pnpm build` and `pnpm format:check` all exit 0.

### Feature 14 — Instrument and holiday calendar seed  *(2026-08-21)*
- Decision: **refresh and seed are separate acts.** `fetch-reference-data.mts` hits NSE and writes committed JSON; `seed-reference.mts` reads that JSON and upserts through the service role, offline. Seeding therefore cannot fail because an undocumented upstream changed shape, and a data change arrives as a reviewable diff rather than 200 silent row updates.
- Decision: the seed authenticates as the **service role**, not through `TEST_DATABASE_URL`. Both reference tables grant `select` only, and loading them is the administrative act that key exists for; a variable named for tests should not become load-bearing for operations.
- Decision: nothing is ever deleted. Upsert by primary key, so a symbol dropped from the index keeps its row — holdings and trades reference it.
- Decision: holidays are stored **exactly as NSE publishes them**, weekend entries included. The published list contains Sunday 15-Feb-2026; dropping it would be an editorial judgement about a published calendar, and `isTradingSession()` decides weekends independently.
- **Finding — Twelve Data's free plan carries no NSE symbols at all.** Verified against the live API with a real key: `AAPL` returns a quote, while `RELIANCE` with or without `exchange=NSE` returns 404 "available starting with the Grow or Venture plan". An entitlement limit, not a symbol-format problem. The provider is dropped rather than shipped as a permanently-false branch, and `library-docs.md`'s standing TODO ("nothing about this provider has been confirmed") is replaced with the transcript.
- **Finding — the first probe reported "200 symbols do not resolve on Yahoo", and every one of those was a 429.** Probing four at a time with a 250ms pause — roughly 16 requests a second — got the IP throttled, and the script recorded the throttling as a verdict on the symbols. That version would have condemned a perfectly good universe, and been believed. The probe now treats only a 404 as a verdict, backs off on 429, aborts the run if throttling persists, and says explicitly that it is not a verdict on any symbol. Results are cached to a gitignored `.cache/` so a throttled run resumes rather than restarting, which is what kept re-tripping the block.
- Gotcha: `curl` returned 200 while `node fetch` returned 429 for the same URL moments apart, which looked like a client-fingerprint difference and was not — it was the recovery window. Once properly blocked, both clients and both Yahoo hosts returned 429 together. Chasing the wrong hypothesis cost a round of header experiments.

With Twelve Data ruled out and NSE's own `quote-equity` answering 403 behind Akamai even with a full browser handshake, no live source remains. F15 still builds the chain, breaker, limiter and provenance helpers against a fake provider — a real provider drops into a finished chain, not the reverse. The probe ships behind `--probe` rather than being deleted, and `nifty200.json` records `yahoo_validated: false` so nobody downstream mistakes "seeded" for "verified". **Open risk:** `/` and `/about` promise "real NSE prices, honestly delayed"; either Yahoo lands or that copy is reconciled before F39 deploys.
- Evaluated and rejected: `jugaad-py/jugaad-data`. Python, against a Node + Deno runtime; and the endpoint its `NSELive.stock_quote()` wraps returns 403 from here through the same cookie handshake that works for the holiday calendar, so porting it would not help either. Its licence file is `LICENSE.YOLO.md`.
- **Finding — the seeded universe broke a cascade assertion that had only ever passed on an empty database.** `02-constraints-money` queried `public.funds` unscoped as the owning role, where RLS does not filter. Five suites also hand-built instrument fixtures that now collide with real rows, and `01-rls-identity` had to clear the default watchlist F13 seeds before asserting on its own. `02-bootstrap` now empties `instruments` deliberately, because before F14 its FK-safe path was only untested rather than proven.
- Verified: `pnpm seed` run twice reports 200 and 20 both times — one universe, not a doubled one. A re-run of the fetch is byte-identical (sha256 compared), and Prettier agrees with the script's output, so there is no format war; only `fetched_on` changes on a later day, which is the point of recording it.
- Verified: `pnpm test:db` 8 files / 148 assertions. `03-reference-data.sql` was observed failing before the seed — `0 >= 190`, NULL descriptions — so it reads real rows rather than restating the seed file. Republic Day is stored on 2026-01-26, which is the timezone bug the hand-rolled date parser exists to prevent.
- Verified: F13's deferred half now passes — a fresh signup receives ten watchlist rows in the declared order, checked inside a rolled-back transaction that left nothing behind.
- Verified: `pnpm lint`, `pnpm typecheck`, `pnpm test` (108), `pnpm build` and `pnpm format:check` all exit 0.

### Feature 13 — Account bootstrap on first sign-in  *(2026-08-21)*
- Decision: **client-ID generation is its own function.** `generate_client_id()` is separate from `handle_new_user()` only because the retry bound cannot otherwise be proven — a pgTAP transaction can `create or replace` it and roll back. Attempts are counted with a **sequence**, since `nextval()` is not rolled back by the failed statement it is measuring.
- Decision: **the watchlist seeds by `INSERT…SELECT` against `instruments`.** F14 populates that table and runs *after* this feature, so a plain insert would violate the foreign key today. FK-safe by construction, idempotent, and it needs no change when F14 lands. `with ordinality` keeps the list order rather than the planner's.
- Decision: **no backfill.** The one pre-existing `auth.users` row was deleted and re-created by signing in again, keeping signup as the only path that ever creates an account.
- Decision: **₹1,00,000 is a literal in SQL**, pinned from both sides — pgTAP asserts a bootstrapped account holds exactly it, `constants.test.ts` pins the TypeScript constant, and both cite `trading-contract.md` §11 rather than each other.
- **Finding — `revoke execute … from public` did not revoke it.** `has_function_privilege('authenticated', 'public.handle_new_user()', 'execute')` was still true after the first migration: Postgres grants EXECUTE to PUBLIC, but Supabase *additionally* sets default privileges granting it directly to `anon`, `authenticated` and `service_role`, which a revoke from PUBLIC does not touch. `handle_new_user` is `security definer`, so a callable copy would have been a hole. Same shape as F07B's table-grant finding, and it is the assertion that caught it. Fixed in a second migration rather than by rewriting the first.
- **Finding — the trigger broke three older suites, and that is what it should do.** `01-rls-identity`, `01-rls-money` and `02-constraints-money` all inserted `auth.users` and then hand-built the profile, funds and ledger rows the bootstrap now creates. Their fixtures pin values with `update` instead of re-creating rows.
- **Finding — a cascade assertion was passing only because the database was empty.** `02-constraints-money`'s "deleting a profile takes the whole account with it" ran `select user_id from public.funds` **unscoped** as the owning role, where RLS does not filter. The first real signup put a genuine account in that table and the assertion failed. It is now scoped to the fixture user; the equivalent queries in `01-rls-*` are safe because they run under `set local role authenticated`.
- Gotcha: a trigger function cannot be called directly — Postgres refuses with `0A000`. The planned "re-running the bootstrap is idempotent" assertion was therefore unprovable as written, and was replaced with the claim that is actually reachable and actually matters: a repeat sign-in **updates** `auth.users` rather than inserting, and the trigger is scoped to INSERT, so no second helping of cash appears.
- Verified by falsification: with the retry bound cut to 3 and the balance to 99999, five assertions fail — the exact-ten count, both money comparisons, the ledger row and the repeat-sign-in balance. Restored and green.
- Verified: `pnpm test:db` 7 files / 134 assertions, `02-bootstrap.sql` 30/30. Tier 3 runs two concurrent signups on separate backends: both complete, client IDs differ, both hold ₹1,00,000 and exactly one `SIGNUP_CREDIT`; `afterEach` removed both accounts and `auth.users` returned to holding only the real one.
- Verified end to end on the real Google account: after deleting and signing in again, the trigger produced `ZR488045`, the name copied from the identity, `theme = 'dark'`, 100000.00 / 0.00 / 100000.00, one `SIGNUP_CREDIT`, §12.1 and §12.2 both holding, and an empty watchlist — correct until F14 seeds `instruments`. `/dashboard` renders the client ID and **₹1,00,000.00**, which is also the first read of a money table through a real session rather than through pgTAP.

### Feature 12 — Google sign-in and route protection  *(2026-08-21)*
- Decision: **sign-in is initiated server-side**, by a `<form>` posting to a Server Action that calls `signInWithOAuth` and redirects to the URL it returns. ### Feature 11 — Database schema: funds, orders, and portfolio  *(2026-08-21)*
- Decision: **the money tables grant `select` and nothing else.** No client role holds insert, update or delete on any of the six, and no write policy exists — every write arrives through a `security definer` function. `code-standards.md` already forbade a Server Action writing them directly, so a write grant would have existed only to be unused.
- Decision: **three §12 identities encoded as CHECK constraints** — 8 (a non-`OPEN` order holds no margin), 12 (longs hold no collateral and no reference price, shorts carry both) and 6 (`charge_breakdown` sums exactly to `charges`) — alongside all-or-nothing fills, `limit_price` presence, and the zero-quantity rules.
- Decision: **that choice constrains F23/F24, and `code-standards.md`'s `execute_order` example was corrected for it.** A CHECK is not deferrable, so setting `status = 'REJECTED'` and *then* calling `release_margin` — exactly what that example did — now fails on the first statement with 23514. The margin must be retired before the status leaves `OPEN`, which is the ordering the contract already implied. A new rule in code-standards states it directly.
- Decision: foreign keys cascade from `orders` and from `profiles`; `reset_account` still deletes each table explicitly per §11, so the cascade is a backstop rather than the mechanism.
- **Finding — a CHECK constraint passes when its expression evaluates to NULL, and identity 6 was bypassable because of it.** The sum check reads seven keys with `->>`; a missing key yields NULL, the sum becomes NULL, the comparison becomes NULL, and the row is accepted. Observed, not theorised: a trade with `charges = 999.99` and a breakdown of `{"brokerage":0}` was stored without complaint. §12.6 was being enforced only for rows that already had every component — precisely the rows that were never going to violate it.
- **Gotcha — the first fix reproduced the same defect one level up.** A shape check reading `jsonb_typeof(... -> 'stt') = 'number'` also goes NULL for an absent key, so `true and NULL` is NULL and the constraint passed exactly as before. Caught only because the probe was re-run after applying it rather than assumed fixed. The working form wraps each in `coalesce(..., '')`, and this time the expression was evaluated against four malformed documents in a plain `SELECT` **before** being written into a migration. Three migrations rather than one, and the history shows why.
- Gotcha: the `orders_limit_price_iff_limit` constraint caught the seed data for the index benchmark — LIMIT rows inserted without a price, intending to set it in a follow-up `UPDATE`. The constraint working on its author is a reasonable first customer.
- Gotcha: dropping `positions_collateral_on_shorts_only` reddens its own assertion *and* the §12.11 positive control further down, because the row the first case now successfully inserts collides on the primary key with the row the control tries to insert. Worth knowing before reading a falsification result as two separate failures.
- Verified **by falsification, seven ways**, each break inside a transaction that rolls back so the production schema is never left modified: dropping identity 8, identity 12, identity 6 and the breakdown shape check each reddens its named assertion; dropping `funds_read_own` reddens the owner-read case; granting `authenticated` update on `funds` reddens both the refusal case and the "SELECT and nothing else" grant assertion. Replacing the trades cascade with a plain foreign key turns the suite red through a 23503 on the DELETE rather than a `not ok` — red either way, and recorded as what it is rather than rounded up.
- Verified: four migrations applied cleanly, a second push reports up to date, `migration list` shows five entries. Types regenerated — 15 tables, 7 enums, no `: any`.
- Verified: 100 pgTAP assertions across six files. The matcher's partial index is used at 20,200 orders with 200 open — Index Scan on `orders_open_by_symbol_idx`, not a Seq Scan.
- Verified: every table empty afterwards; all probing ran in rolled-back transactions.
