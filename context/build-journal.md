## How this file is maintained

This file grows for the life of the project and is **not** part of the session read order.
Nothing here is required to make a decision — anything that still constrains future work gets promoted to `constraints.md`, which is the file consulted during ordinary work.
That separation is what keeps the cost of knowing "what binds" from growing with the length of the build.

- **Append a dated entry after every completed feature**, under the current phase: decisions made, gotchas hit, verification results.
- **Compact at every phase checkpoint, never continuously.** When a phase closes:
  1. **Promote** anything from that phase that still binds into `constraints.md`, filed under its topic.
  2. **Collapse** the phase's per-feature entries into a handful of summary bullets.
  3. **Drop every `Verified:` line** — it has done its job once the next feature passes.
- Only the current phase keeps full per-feature detail. Earlier phases stay compacted, newest first.

Compaction is recoverable: this file is committed, so `git` history holds every detail ever removed.

## Phase 1 — Foundation & Public Site

### 1.00.01 — Muted token contrast fix  *(2026-08-21)*
Not a numbered feature: F38's palette work, pulled forward because every page shipped in Phase 1 was failing it.
- Decision: **both muted tokens change in both themes**, not just light. The measurement that prompted this was the light-mode failure, but `--color-muted` at #707a8a was also 3.02:1 on `--color-surface-elevated` in dark — the token had never cleared AA anywhere. Dark becomes muted #929aa5 / muted-strong #b6bec9; light becomes muted #5a6472 / muted-strong #3d4552.
- Decision: **the light values invert relative to dark.** On a light ground "more prominent" means darker, so light `muted-strong` is darker than light `muted`, the reverse of the dark theme. Leaving them un-overridden had made `muted-strong` *less* prominent than `muted` in light — the hierarchy backwards, not merely dim.
- Decision: the fix is **machine-checked**, matching how F02 pinned the brand invariant. `theme-tokens.test.ts` now parses the stylesheet, computes every foreground/surface contrast ratio in both themes, asserts AA, and asserts the `muted < muted-strong < body` ordering on the *worst* surface — a hierarchy that only holds on the page background is not a hierarchy.
- Gotcha: **a scripted theme toggle fabricates contrast failures.** Adding `.light` via `classList` and measuring immediately reported 17 failing elements on `/legal`; loading the page genuinely in light theme reported 4. Elements carrying `transition-colors` return stale computed colours after a scripted class change, and no settle delay fixed it — `getComputedStyle` at the element returned the correct *variable* while `color` still resolved to the old value. Diagnosing this cost more time than the fix. **Set the stored theme, reload, then measure.** Recorded in `constraints.md`.
- Gotcha: chasing that phantom ran through the compiled CSS looking for a cascade problem — rule order, `@layer` precedence, `@property` registration with `inherits: false`, a stray `.dark` block. All were fine. The stylesheet was never the problem; the measurement method was.
- Verified **by falsification, three ways**: restoring the old dark `--color-muted` fails the AA assertion naming that token; deleting the `.light` overrides fails the "does redefine" assertions for both tokens; swapping the two light values fails the hierarchy assertion. All reverted, 93 assertions green.
- Verified: `pnpm audit:a11y` now scores **100 with zero contrast nodes** on `/`, `/about`, `/pricing` and `/legal` — the failure open since F04 is closed.
- Verified by loading each theme for real on `/legal`: **dark 0 failing of 82 text elements; light 4 of 82**, and all four are the same brand yellow at 1.37:1 — the wordmark and two inline prose links. That is the separate `text-brand` issue, still filed against F38 and untouched here.
- Verified: `pnpm lint`, `pnpm typecheck`, `pnpm test` (93) and `pnpm build` all exit 0.

### Feature 02 — Design system and theme tokens  *(2026-08-21)*
- Decision: shadcn's token vocabulary is **bridged** onto this project's in a `@theme inline` block, never merged.
